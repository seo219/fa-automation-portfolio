## 1. 팔레타이징 · 계산과 장비 제어 분리

### 함수 구조

```text
execute_pick_and_place()
├─ offset_pose_on_tool_z()   접근·회수 좌표 계산
├─ generate_pallet_targets() 층·행·열별 타겟 생성
├─ gripper_open/close()      디지털 출력 제어
├─ move_linear()            명령 전송·응답 검사·완료 대기
│  ├─ check_response()
│  └─ wait_until_motion_done()
└─ move_home()              작업 종료 후 복귀
```

좌표를 만드는 함수와 실제 장비에 명령하는 함수를 나눠, 적재 패턴과 이동 절차를 각각 읽을 수 있도록 구성했습니다.

### 타겟 생성

2×2 평면의 순서를 목록으로 정의하고 층을 반복합니다. 원본은 각 타겟을 pose·column·row·layer 키가 있는 딕셔너리로 저장합니다.

```python
# 원본 generate_pallet_targets()의 핵심 로직을 요약한 의사 코드
for layer in range(layers):
    for column, row in pallet_order:
        target = list(base_pose)
        target[0] += column * spacing_x
        target[1] += row * spacing_y
        target[2] += layer * layer_height
```

기준 좌표를 복사한 뒤 오프셋을 더하므로, 한 타겟 계산이 기준 목록을 직접 바꾸지 않습니다. 현재 원본의 평면 순서는 2×2 전용이며, 다른 행·열 수에는 ValueError를 발생시킵니다. 임의 크기 팔레트 지원으로 소개하지 않습니다.

### TCP 방향의 접근점

`offset_pose_on_tool_z()`는 회전행렬의 세 번째 열을 TCP +Z 방향 벡터로 사용합니다. 자세는 유지하면서 해당 벡터에 거리를 곱해 XYZ에 더합니다. 단순히 베이스 Z만 바꾸는 접근과 구분됩니다.

### 이전 동작의 완료 상태를 오인하지 않기

`wait_until_motion_done()`은 명령 전 motion_id를 기억하고, 새 ID 또는 이동 중 상태를 관찰한 뒤 목표 도달과 이동 종료를 확인합니다. 원본은 `time.monotonic()` 기반 제한 시간을 두고 완료되지 않으면 TimeoutError를 발생시킵니다.

이 설명은 현재 원본 코드 구조를 읽은 결과입니다. 실제 SDK·장비의 상태 갱신 순서까지 검증한 것은 아닙니다.

## 2. PLC 연동 · 요청 한 번에 동작 한 번

`pc_plc_robot.py`는 다음 흐름을 반복합니다.

1. Type3E로 M100 비트를 읽습니다.
2. 내부 is_home 값에 따라 HOME 또는 ZERO로 이동합니다.
3. 목표 도달 후 M101을 1초간 ON합니다.
4. M100 OFF를 확인한 뒤 다음 요청을 받습니다.
5. 종료 시 DONE 초기화와 통신 연결 해제를 시도합니다.

**핵심:** 시작 입력이 계속 ON이어도 모션이 반복 실행되지 않도록 요청 해제 대기를 둡니다.

**개선할 점:** 초기 HOME 가정, 통신 오류 후 내부 상태 동기화, START OFF 대기 타임아웃은 추가 검토가 필요합니다. [제어 관점 상세](plc-robot-handshake.md)

## 3. TCP 상대 이동 · 코드와 주석 확인

`tcp_rel.py`는 이동 명령의 응답을 확인하고 오류 시 모션 정지를 시도합니다. 이동 전후 TCP 위치도 출력합니다.

현재 원본 주석은 Tool Z +10 mm라고 되어 있지만, 실제 전달 인자는 `[0, 0, 30, 0, 0, 0]`입니다. 따라서 문서에서는 **코드 인자 기준 +30 mm**로 설명합니다. 이 포트폴리오 작업에서는 원본 저장소의 코드를 수정하지 않았습니다.

## 4. 5×5 그리드 · 데이터로 반복 동작 표현

`25repeat.py`는 행·열 인덱스로 25개 위치를 만들고, 각 위치를 접근·타겟·회수 세 자세로 저장합니다. 이송 루프는 인접 위치 사이를 24번 이동하도록 구성되어 있습니다.

현재 원본의 기준 위치·자세 값 여섯 개가 비어 있어 그대로는 구문 실행이 불가능합니다. 코드 구조를 보여주는 자료이며 실행 가능한 완성 예제로 분류하지 않습니다.

## 실행 환경과 현재 상태

| 항목 | 필요한 준비 |
|---|---|
| 언어·라이브러리 | Python, neuromeka / PLC 연동은 pymcprotocol 추가 |
| 통신 설정 | 장비별 연결 정보와 접근 가능한 네트워크 |
| 작업 설정 | 실제 TCP·툴 프레임, 타겟·접근점, DO 채널 |
| 호환성 | 실제 사용 SDK 버전과 장비 응답 형식 확인 |
| 미설정 파일 | 25repeat.py의 기준 좌표·자세 입력 필요 |

이 저장소에는 장비 실행 스크립트를 복제하지 않았습니다. 원본 코드에는 가져오기 단계의 장비 객체 생성과 최상위 실행 구문이 있어, 오프라인 코드 확인을 위해 무심코 import하는 방식은 적합하지 않습니다. 문서 작성 과정에서는 정적 코드만 읽었으며 장비 연결·모션·성공률 시험은 수행하지 않았습니다.

## 팀 프로젝트와의 연결

[AI 로봇 윷놀이 · SO-101 로봇암](ai-yutnori-robot-arm.md)은 별도의 팀 프로젝트입니다. Python 스크립트 기반 동작과 집기 보정 흐름은 발표자료로 확인했지만, 현재 팀 저장소에 접근되지 않아 함수·클래스 단위 코드 분석은 포함하지 않았습니다.

위 Indy·PLC 실습 코드를 SO-101 팀 프로젝트의 코드로 혼동하지 않도록 구분했습니다.
